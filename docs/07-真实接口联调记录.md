## 1 联调结论

- 后端是按同一份《后端技术方案》实现的，路径、状态机、错误码基本一致；但**字段命名、返回结构、写接口约束**与前端 Mock 契约存在差异，已在 `src/api/real.ts` 适配层消化。
- 真实数据链路已跑通：登录 → 工作台 → 计划列表/详情 → 数据回收（手工录入）→ 数据看板 → 报表创建/下载；草稿创建、状态流转、删除均已验证。
- 数据库初始为空（只有 root 账号），演示数据通过后端接口播种，脚本：`scripts/seed-real.py`。

## 3 字段映射（后端 → 前端 DTO）

### 3.1 登录

后端返回 `{ token, tokenType, expiresIn: "2h", user: { id: "3", username, displayName, role } }`（id 为字符串，无 permissions）。
前端映射：`expiresIn` 字符串转秒；权限按角色补齐（admin → `['*']`，user → 固定权限集）。

### 3.2 计划列表 / 详情

| 后端字段 | 前端字段 | 说明 |
|---|---|---|
| `id: "1"` | `id: 1` | 统一转 number |
| `objective` | `goal` | impression / click / lead |
| `budget: "360000.00"` | `budget` | 字符串金额 |
| `targetImpressions: "16880000"` | `targetImpressions` | 字符串 |
| `actualImpressions / actualReach / actualClicks / actualCost` | `impressions` 等 | 空值为字符串 `"null"`，映射为 0 |
| `completionRate: number \| null` | `completionRate: string \| null` | 无数据时后端给 0，前端判断 impressions=0 显示「—」 |
| `vendors[{id,code,name,platform}]` | `vendors[{id,name,code}]` | — |
| `createdBy: "3"` | `creator.id` | 后端不返回创建人姓名，页面显示「—」 |
| 无 `dailyBudget` | `dailyBudget` | 前端按 `budget ÷ 排期天数` 估算展示 |
| 无 `bidType / contractNo / finishedAt / closedAt / reportNo / dataUpdatedAt` | 同名 | 详情页按空值处理；数据更新时间取分日数据最大 `updatedAt` |

详情页完成率改为「所选周期分日曝光合计 ÷ 计划目标」在前端计算，避免后端详情页 `completionRate=0` 的问题。

### 3.3 分日数据

`GET /campaigns/:id/stats?from&to` → `{ campaignId, from, to, totals, rows[] }`
`rows[] = { statDate, impressions, reach, clicks, cost, source, updatedAt }`
映射为 `PageResult<DailyStat>`；`source=mock` → `isMock=true`。

### 3.4 人群分布

`GET /campaigns/:id/dimensions?type=region|gender|age` → `{ campaignId, items[{dimType, dimValue, impressions, reach, clicks}], grouped }`
映射：`dimValue → dimName`，`ratio` 由前端按合计计算；按 `impressions` 降序。

### 3.5 数据看板

| 接口 | 返回 | 映射 |
|---|---|---|
| `/dashboard/summary` | `{ targetImpressions, impressions, reach, clicks, cost, runningCampaigns, dataUpdatedAt, completionRate: number, clickRate: number, cpm }` | `DashboardSummary`；无环比字段，环比显示「—」 |
| `/dashboard/trend` | `[{ statDate, impressions, reach, clicks, cost }]`（数组） | `TrendPoint { date, actual, target: '0', clicks }`；无目标线时前端只画实际线 |
| `/dashboard/dimensions?type=` | `{ items[{dimType, dimValue, impressions,...}], grouped }` | 按 `dimType` 过滤后映射 |
| `/dashboard/channels` | `[{ channel, impressions }]` | 渠道编码 → 中文名 |

### 3.6 报表

- 创建：`POST /reports { type: 'campaign' | 'daily', campaignId?, from?, to? }`，返回 `{ id, type, status, fileName, downloadUrl }`（id 为 UUID）。
- 列表：`GET /reports?page&pageSize` → `items[{ id, type, campaignId, status, fileName, createdAt, finishedAt }]`，无文件大小。
- 下载：`GET /reports/:id/download` 返回 xlsx 二进制流。
- 前端：类型收敛为「结案报告（campaign）/ 数据明细（daily）」，展示名改为 `结案报告_20261123-1354.xlsx`；下载优先使用友好文件名。

### 3.7 其他

| 接口 | 说明 |
|---|---|
| `/projects/` | 返回数组（不是分页）；只有 `budget`，无 `usedBudget`，前端按该项目下计划预算累加 |
| `/vendors` / `/vendors/active` | 列表 / 启用列表；`campaignCount` 已有 |
| `/users` | 用户管理接口齐全（管理端二期可直接用） |
| `/sync-tasks` | `{ id, campaignId, triggerType, adapter, status, rowsAffected, message, startedAt, finishedAt }`；无计划名，前端用计划列表关联 |
| `/logs` | `{ id, objectType, objectId, action, before, after, operatorName, ip, createdAt }`；动作名如 `mock_generate`、`save_mock_profile` |
| `/campaigns/:id/mock-profile` | `dimRatio` 为「名称: 比例」映射；`ctr/cpm/frequency` 为数字 |
| `/stats/import` | multipart 文件上传；错误返回 422 + `details[{row, code, message}]` |
| `/stats/import/template` | 返回模板 xlsx 文件流 |

## 4 后端坑位与前端处理

1. **写接口必须带 JSON body**：空 POST 会返回 `1001 Body cannot be empty when content-type is set to 'application/json'`。请求层对 POST/PUT/PATCH/DELETE 自动补 `{}`。
2. **dimRatio 必须是映射**：`{ region: { 江苏省: 0.32 }, gender: {...}, age: {...} }`；传数组会让生成接口 500（`Unknown column 'NaN'`）。
3. **模拟生成不清理区间外数据**：重复生成只覆盖 `from~to`，缩小范围会残留旧行。演示数据统一按完整排期生成。
4. **人群维度不按日期过滤**：看板「地域/性别/年龄」是计划全周期累计，与周期 KPI 口径不同，已在卡片副标题标注。
5. **汇总口径**：`summary.completionRate = 周期 impressions ÷ 计划总 target`（target 不按周期折算），14 天窗口约 48%。KPI 提示已注明「后端口径」。
6. **计划列表 completionRate 无数据时为 0**：前端判断实际曝光为 0 时显示「—」。
7. **报表类型只有 campaign / daily**：前端只展示「结案报告」「数据明细」两个入口。
8. **id 类型不统一**：计划/用户为数字字符串，报表/同步/日志为 UUID；前端类型放宽为 `string | number`。
9. **无字典接口、无令牌续期**：前端内置字典，401 直接跳登录。
10. **人群维度数据依赖 mock 生成**：手工录入接口不支持 dims，真实模式下隐藏「同时录入人群分布」开关。

## 9 后端 v3 变更（管理端合并期间，2026-11-23）

1. **渠道表成为计划创建前置条件**：`POST/PUT /campaigns` 会校验渠道存在且启用，否则 400「投放渠道不存在或已停用」。后端重置库后必须先播种渠道，`scripts/seed-real.py` 已加入 `ensure_channels()`。
2. **渠道管理接口可用**：`GET /channels`、`POST /channels`、`PUT /channels/{id}`、`DELETE /channels/{id}`，字段 `code / name / bidType / status / sortNo / remark`。
3. **`/dicts` 的渠道与年龄段来自数据库**：`channels` 表为空时，向导与字典页均无渠道数据；管理端字典页渠道可编辑，年龄段与指标口径仍只读（无写接口）。
4. **清空数据**：`DELETE /campaigns/{id}/stats` 已支持，管理端模拟参数页与详情页均已接入。
5. 管理端五个页签已并入用户端工程（见 `docs/10-管理端合并说明.md`），接口复用 `/users`、`/vendors`、`/channels`、`/dicts`、`/logs`、模拟参数相关接口。

> 2026-11-24：`POST /campaigns/{id}/sync` 返回字段由 `days` 调整为 `updatedDays`，并新增 `message`（如「计划尚未开始」）。前端已兼容新旧字段；未开始的计划同步返回 0 天属于后端正常行为。

> 2026-11-24：`GET /dashboard/trend` 的「计划曝光」在 2026-11-24 返回 162,449,553，其他日期约 57.8–75.1 万，疑似把累计目标写到了单日，导致趋势图 Y 轴被拉到 2 亿、实际曲线贴底。前端图表已过滤该类异常点；建议后端修正目标分摊，并同步检查 `/dashboard/summary` 的计划曝光总量。
