## 5 Mock 层设计

- **单一数据源**：`src/mock/db.ts` 用 `localStorage`（key `adflow.mock.db.v1`，version 2）持久化整个演示数据库；版本不一致自动重播种。
- **请求链路**：页面 → `api/*.ts` → `request()` → `VITE_USE_MOCK !== 'false'` 时走 `mockRequest`，带 90–260ms 抖动；返回与后端一致的 `{ code, message, data, traceId }` 信封。
- **业务规则**：状态机迁移、权限校验（admin/user）、名称重复（2002）、预算超限（2003）、状态不允许（2001）、厂商停用（2005）、导入校验（3001/3002）、模拟参数范围（3003）均在 Mock 中实现，页面错误处理与字段定位可直接复用。
- **演示数据**：项目 1 个、厂商 6 家、计划 9 条（覆盖 7 种状态）、分日数据约 60 天、三组人群维度；主计划严格对齐验收材料：目标 16,880,000、实际 17,125,369、曝光人数 196,942、点击率 1.15%、完成率 101.45%。
- **生成算法**：`mulberry32(seed)` 固定种子、四种曲线、±15% 波动、按频次/点击率/千人成本折算、最大余数法拆维度、覆盖写入——与后端方案一致，切真实接口时数值可复现。
- **重置**：顶栏刷新图标 → 二次确认 → 重新播种并刷新页面（对应方案「一键重置脚本」的前端形态）。
- **切真实接口**：`.env.production` 设 `VITE_USE_MOCK=false` 与 `VITE_API_BASE`，`request()` 自动改走 axios（已实现 Authorization / X-Trace-Id / 401 单飞 / blob 下载）。

## 6 与契约的对照

- 已按契约实现：auth、projects、dicts、campaigns（列表/创建/详情/修改/删除/状态动作/厂商）、stats（查询/录入/调节/维度/同步/导入）、dashboard（summary/trend/dimensions）、reports（创建/列表/下载）、vendors、mock-profile/generate、logs。
- 契约中标注「待后端补充」的接口（`/users`、`/dicts` 写、`/auth/refresh`、`/withdraw` 等），本期以实现路径为准：`withdraw` 已按契约补齐 Mock；用户与字典维护页不在本期范围；续期暂以「401 跳登录」处理。
- 与文档的已知差异（均为演示环境取舍）：
  1. 报表 **PDF 暂时禁用**，只提供 xlsx（PDF 模板需后端生成）。
  2. 素材页签为只读空态，未接素材库。
  3. 「直接发布」仅管理员可选，Mock 中直接置为投放中并生成单号。
  4. 多渠道建计划由 Mock 按 `channels[]` 循环创建，返回 `ids[]`（契约建议形态）。
  5. 环比在「上期数据覆盖不足 30%」时返回空，页面显示「—」，避免失真百分比。
  6. 图表使用完整 ECharts 打包；首屏 gzip 约 428KB，低于方案 500KB 目标，后续可按需引入再压缩。
