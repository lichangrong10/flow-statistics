## 2 详细规格

### R1（P0）手工录入支持人群维度

**现状**：`POST /campaigns/{id}/stats` 只接受 4 个数值，维度数据只能由 mock 生成器产出。前端「同时录入人群分布」开关因此被隐藏，文档 4.5.1「合计必须等于总曝光」无法验收。

**建议**：扩展请求体（不传 `dims` 时保持现有行为，向后兼容）：

```http
POST /api/v1/campaigns/1/stats
{
  "statDate": "2026-11-20",
  "impressions": 1000000,
  "reach": 12000,
  "clicks": 120,
  "cost": 1200.00,
  "dims": {
    "region":  [{ "key": "jiangsu", "name": "江苏省", "impressions": 320000 }],
    "gender":  [{ "key": "male",    "name": "男",     "impressions": 460000 }],
    "age":     [{ "key": "25-29",   "name": "25-29",  "impressions": 240000 }]
  }
}
```

**校验（服务端）**：
- 三组维度合计分别等于 `impressions`，否则 `1001` 并带字段级错误；
- 维度项 `impressions` 非负整数；
- 同一计划同一日期重复提交按覆盖处理（与现有每日 UPSERT 一致）；
- 维度写入 `dim_stat` 时带上 `stat_date`（见 R6），否则请至少保证可按计划覆盖。

**响应**：`{ "statDate": "2026-11-20", "dimsValid": true }` 或沿用现有 `{ code:0 }`。

**验收**：录入一天带维度数据后，`GET /campaigns/1/dimensions?type=region` 能查到当日维度且合计等于当日曝光。

### R2（P0）看板/工作台指标卡环比

**现状**：`GET /dashboard/summary` 无环比字段，前端指标卡只能显示「—」。

**建议**：请求增加 `compare=previous`（默认不返回），响应增加 `compare` 对象：

```http
GET /api/v1/dashboard/summary?projectId=1&from=2026-11-10&to=2026-11-23&compare=previous
```

```json
{ "code": 0, "data": {
  "targetImpressions": "20080000", "impressions": "17125369", "reach": "196942",
  "clicks": "2234", "cost": "202559.98", "runningCampaigns": 3,
  "completionRate": 0.8526, "clickRate": 0.0115, "cpm": 11.83,
  "dataUpdatedAt": "2026-11-23 13:44:55",
  "compare": {
    "targetImpressions": "16880000", "impressions": "15800000", "reach": "181000",
    "clicks": "2050", "cost": "188000.00",
    "completionRate": 0.9360, "clickRate": 0.0113, "cpm": 11.90
  }
}}
```

**约定**：上一周期 = 与 `from/to` 等长的前一区间；上期无数据时返回 `compare: null` 或省略，前端显示「—」。

### R3（P0）趋势接口返回每日计划目标

**现状**：`GET /dashboard/trend` 只返回实际值，前端无法画「实际 vs 计划」双线。

**建议**：每行增加 `target`（当日应完成的目标曝光，可按计划排期与目标均摊）；或响应改为 `{ items: [...], targetTotal }`。

```json
GET /api/v1/dashboard/trend?projectId=1&from=2026-11-10&to=2026-11-23
{ "code": 0, "data": [
  { "statDate": "2026-11-10", "impressions": "572032", "target": "681000",
    "reach": "6655", "clicks": "75", "cost": "6914.06" }
]}
```

### R4（P0）报表能力补齐

文档 4.7 要求**日报、周报、结案报告、数据明细**四类，格式 xlsx + pdf，并支持批量计划导出。当前仅 `campaign` / `daily`、仅 xlsx、无批量、无文件大小、文件名为 UUID。

**4.1 类型与格式**

```http
POST /api/v1/reports
{ "type": "daily|weekly|campaign|detail",
  "format": "xlsx|pdf",
  "projectId": "1",
  "campaignIds": ["1", "2"],
  "from": "2026-11-16", "to": "2026-11-23" }
```

| type | 含义 | 说明 |
|---|---|---|
| daily | 投放日报 | 单日或区间，全部计划 |
| weekly | 投放周报 | 周维度汇总 + 环比 |
| campaign | 结案报告 | 必须指定单条 `campaignId` |
| detail | 数据明细 | 按计划与日期展开原始记录 |

**4.2 批量计划**：`campaignIds` 传多条时，`daily` / `detail` 只导出这些计划；`campaign` 仍限单条。

**4.3 列表补字段**：

```json
{ "id": "uuid", "type": "daily", "format": "xlsx", "status": "success",
  "fileName": "投放日报_20261116-20261123.xlsx", "fileSize": 48120,
  "campaignIds": ["1","2"], "createdAt": "...", "finishedAt": "..." }
```

**4.4 下载**：`GET /reports/{id}/download` 返回文件流，并在 `Content-Disposition` 中给出友好文件名（`filename*=UTF-8''...`）。

**验收**：四种类型×两种格式均可创建并下载；列表能显示文件大小；批量导出的文件只包含所选计划。

### R5（P0）项目返回已用/剩余预算

**现状**：`GET /projects` 只有 `budget`。向导无法准确校验「总预算 ≤ 项目剩余预算」，前端只能把该项目下所有计划预算加起来估算。

**建议**：响应增加：

```json
{ "id": "1", "name": "2026 年太仓分公司全域融数智能投放", "budget": "2000000.00",
  "usedBudget": "1409000.00", "remainingBudget": "591000.00" }
```

`usedBudget` 口径：该项目下所有未删除计划的预算之和（草稿是否计入请明确，并在文档注明）。

---

### R6（P1）人群维度支持周期过滤

**现状**：`dim_stat` 按计划聚合，`GET /dimensions?type=region&from=&to=` 的日期参数不起作用，看板周期与维度口径不一致（前端只能标注「计划全周期累计」）。

**建议**：
- `dim_stat` 增加 `stat_date`（与 `daily_stat` 同粒度），或提供按日维度存储；
- `GET /campaigns/{id}/dimensions`、`GET /dashboard/dimensions` 支持 `from` / `to` 并真实过滤；
- 不传时保持现有全周期行为（向后兼容）。

**验收**：同一计划分别查 11-10~11-16 与 11-17~11-23，维度合计不同且分别等于对应区间曝光。

---

### R7（P1）计划字段补齐：日预算、出价方式、关联合同

**现状**：`POST/PUT /campaigns` 只接受 `budget`，文档 4.3.2 中的「日预算」「出价方式」「关联合同」没有字段，前端采集后无法保存，详情页显示派生值或「—」。

**建议**（三选一，推荐 A）：

- **A. 补齐字段**：`dailyBudget`（number，两位小数）、`bidType`（`cpm`/`cpc`）、`contractNo`（string ≤32），创建/修改/详情/列表均可返回；
- B. 明确这三项不在本期范围 → 前端从向导与详情中隐藏；
- C. 允许存入 `extra` JSON 字段并原样返回（不推荐，不利于查询）。

**校验**：`dailyBudget > 0`、`dailyBudget ≤ budget`、`contractNo` 长度限制。

---

### R8（P1）计划详情补齐汇总字段

**现状**：`GET /campaigns/{id}` 没有实际汇总与时间戳，且 `completionRate` 在详情接口恒为 `0`（列表接口正常）。前端只能再拉一次分日数据自行求和。

**建议**：详情响应补充——

```json
{ "actualImpressions": "16880000", "actualReach": "194111", "actualClicks": "2233",
  "actualCost": "202559.98",
  "completionRate": 1.0,
  "dataUpdatedAt": "2026-11-23 13:44:55",
  "creatorName": "系统管理员",
  "submittedAt": "...", "finishedAt": null, "closedAt": null, "reportNo": null }
```

并修正 `completionRate` 计算（当前详情返回 0，与列表不一致）。

---

### R9（P1）同步结果与同步记录补充信息

**建议**：
- `POST /campaigns/{id}/sync` 响应增加 `days`、`added`（新增天数），方便提示「已同步 N 天，其中 M 天为新增」；
- `GET /sync-tasks` 每行增加 `campaignName`、`durationMs`（或保留 `startedAt/finishedAt` 由前端算），当前列表只能显示「计划 #id」。

```json
{ "id": "20", "campaignId": "8", "campaignName": "十月品牌月报计划",
  "triggerType": "manual", "status": "success", "rowsAffected": 30,
  "days": 30, "added": 2, "durationMs": 1200,
  "message": "生成 2026-09-09 至 2026-10-08 的模拟数据",
  "startedAt": "...", "finishedAt": "..." }
```

### R10（P2）清空单计划模拟数据

**现状**：只能覆盖生成；演示前想清空某条计划的数据无法做到（缩小生成区间会残留旧行）。

**建议**：`DELETE /campaigns/{id}/stats`（或 `POST /campaigns/{id}/mock/clear`），删除该计划全部分日与人群数据，写审计日志。返回 `{ "cleared": true, "deletedDays": 30 }`。

---

### R11（P2）字典接口

**建议**：`GET /dicts` 返回渠道、年龄段、兴趣、平台、指标口径，带 `version`：

```json
{ "version": "2026-11-23", 
  "channels": [{ "code": "douyin", "name": "抖音", "enabled": true, "bidType": "cpm" }],
  "ages": [{ "code": "18-24", "name": "18-24 岁" }],
  "interests": [{ "code": "digital", "name": "数码家电" }],
  "metrics": [{ "code": "ctr", "name": "点击率", "formula": "clicks/reach", "decimals": 2 }] }
```

前端按 `version` 缓存；无此接口时前端使用内置字典，不影响功能，只影响运营可配置性。

---

### R12（P2）令牌续期

**建议**：`POST /auth/refresh`（Bearer 旧令牌）返回 `{ "token": "...", "expiresIn": 7200 }`。前端在到期前 5 分钟静默续期；无此接口时 401 直接跳登录（当前行为）。

---

### R13（P2）无数据时完成率返回 null

**现状**：计划无分日数据时，列表 `completionRate` 返回 `0`，前端需靠「实际曝光为 0」判断显示「—」。

**建议**：无数据或目标为 0 时返回 `null`，有数据时保留 4 位小数（如 `1.0145`）。

---

### R14（P2）渠道接口返回名称

`GET /dashboard/channels` 建议增加 `channelName`，当前只返回 `channel` 编码，前端依赖内置映射。

---

### R15（P2，可选）写接口允许空 body

当前所有 POST/PUT 必须带 `{}`，前端已统一补齐，不影响使用；如后端愿意放宽 `Content-Type: application/json` + 空 body 的校验，可减少一处前端约定。
