# 排期自动发布 · 后端需求

日期：2026-11-24
提出方：前端
背景：当前业务只保留管理员模式，创建计划时不再有人工审核环节。产品要求：

- 开始日期 **未到**：计划进入「已排期」，不生成投放单号、不开始投放；
- 到达开始日期：后端自动发布，生成投放单号，状态转为「投放中」；
- 创建时开始日期 **已到/就是今天**：直接发布，立即生成投放单号并开始投放。

后端已确认实现自动发布；前端已按规则调整创建流程，并移除手动发布入口，改为「到期自动发布」提示。

## 1 状态定义

| 状态 | 含义 | 是否允许同步数据 |
|---|---|---|
| `draft` | 草稿，可编辑/删除 | 否 |
| `scheduled` | 已审核通过、等待开始日期，未生成投放单号 | 否，返回「计划尚未开始」 |
| `running` | 已发布、投放中，已生成投放单号 | 是 |
| `paused` / `finished` / `closed` | 暂停 / 结束 / 结案 | 按现有规则 |

`pending`（待审核）已从产品流程移除；历史 `pending` 数据由后端迁移或走兼容发布。

## 2 创建接口行为

`POST /campaigns` 只创建草稿；前端随后调用：

1. `POST /campaigns/{id}/submit`
2. 开始日期 > 今天：
   - `POST /campaigns/{id}/approve`
   - 期望状态：`scheduled`
   - `code = null`，`publishedAt = null`
3. 开始日期 <= 今天：
   - `POST /campaigns/{id}/approve`
   - `POST /campaigns/{id}/publish`
   - 期望状态：`running`
   - 生成 `code` 与 `publishedAt`

建议 `approve` 与 `publish` 保持幂等；前端发布接口已兼容「后端仍为 pending」时自动补审核。

## 3 发布接口约束（需要后端确认/修改）

`POST /campaigns/{id}/publish` 当前无论开始日期是否到达都会把状态置为 `running`，需要改为：

- `startDate > 今天`：不转 `running`，保持/返回 `scheduled`，不生成投放单号；
- `startDate <= 今天`：转 `running`，生成投放单号；
- 对 `scheduled` 且已到开始日期的计划，允许手动发布，效果等同自动发布；
- 对已 `running` 计划重复 publish 应幂等或返回明确错误，不能重复生成单号。

## 4 自动发布定时任务

新增后端定时任务（建议每 1–5 分钟一次，时区 `Asia/Shanghai`）：

筛选条件：

```text
status = scheduled
startDate <= 今天（Asia/Shanghai）
endDate >= 今天（或按业务定义处理已过期排期）
```

处理动作（单计划事务内）：

1. 再次校验状态仍为 `scheduled`；
2. 生成唯一投放单号 `code`；
3. 状态改为 `running`；
4. 写入 `publishedAt`；
5. 写操作日志，动作建议 `auto_publish`，操作人显示为「系统」；
6. 并发场景加行锁/乐观锁，避免重复发布。

失败处理：

- 单条失败记录错误日志并重试，不影响其他计划；
- 连续失败达到阈值后告警；
- 重复执行任务不能生成多个单号。

边界：

- 开始日期为今天：当天即发布，不等到次日；
- 时区固定北京时间，不能使用 UTC 日期直接比较；
- `scheduled` 且 `endDate < 今天` 的历史计划：建议自动结束/标记异常，不进入投放；
- 自动发布后，数据同步接口才可返回数据。

## 5 接口返回建议

创建/审核/发布接口返回 `status`、`code`、`publishedAt`，便于前端提示：

- 未来计划创建成功后提示「计划已排期，将在开始日期自动发布」；
- 当天计划提示「发布成功，已生成投放单号」。

## 6 验收用例

1. 今天创建、开始日期 = 明天 → 状态 `scheduled`、无单号；到明天自动变 `running` 并生成单号。
2. 今天创建、开始日期 = 今天 → 状态 `running`、立即生成单号。
3. 未来计划手动点「发布」→ 仍保持 `scheduled`，不提前变 `running`。
4. 自动任务重复执行 → 单号不重复、状态不重复变更。
5. `scheduled` 计划调用同步接口 → 返回 0 天 +「计划尚未开始」。
6. 北京时间 00:00 后，开始日期为当天的计划被任务发布。
7. 操作日志中能看到 `auto_publish`，操作人为「系统」。

## 7 前端当前实现

- 创建时开始日期 > 今天：提交后只执行到 `approve`，停在 `scheduled`；
- 创建时开始日期 <= 今天：`submit → approve → publish`，直接 `running`；
- 前端无法自行「到点触发」，必须依赖后端定时任务；
- 历史 `pending` 计划前端展示为「已排期」，手动发布会自动补审核后再发布。

> 结论：**需要后端改**。核心是发布接口的排期判断 + 自动发布定时任务；只改前端无法实现「到时间自动发布」。
