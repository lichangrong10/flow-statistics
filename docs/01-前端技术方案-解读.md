# 投流统计平台 · 前端技术方案解读

> 来源：《投流统计平台-前端技术方案》TC-ADP-FE-TS-001 V1.3（2026-11-23，内部资料）
> 配套文档：《投流统计平台后端技术方案》TC-ADP-BE-TS-001（同一基线，已交叉比对）
> 用途：开发开工前的统一理解底稿；后续设计、编码、联调、验收均以此对照。

---

## 1 一句话定位

平台把「投放动作」与「投放结果」结构化为**可查询、可核验、可导出**的数据资产。前端承担「看得见、点得动、截得下」：计划可发布、过程可跟踪、结果可核验，并直接支撑**系统截图、现场演示、结案报告**三类交付材料。

当前阶段**只做模拟投流**：不向媒体真实下单，曝光 / 点击 / 消耗由平台按参数生成并支持后台调节，用于流程验证、内部演练与验收演示；后续接真实媒体接口时，**界面与操作习惯保持不变**。

## 2 目标与边界

### 2.1 六条业务目标
| # | 目标 | 落地要求 |
|---|---|---|
| 1 | 统一入口 | 一个界面完成多渠道多厂商计划的创建、审核、发布、暂停、结案 |
| 2 | 厂商可配 | 厂商是平台主数据，一个计划可多选厂商，新增合作方不改代码 |
| 3 | 过程留痕 | 每次状态变更、数据修改记录操作人 / 时间 / 变更内容 |
| 4 | 结果可核验 | 「计划 + 日期 + 人群维度」三级粒度，指标口径固定 |
| 5 | 一屏看清 | 看板 5 秒内回答「投了多少、完成多少、投给谁」 |
| 6 | 交付可用 | 1440×900 与 1920×1080 下可直接截图，无需二次排版 |

### 2.2 边界（前端做 / 不做）
| 前端承担 | 前端不承担 |
|---|---|
| 计划录入、校验、提交与状态展示 | 素材转码、送审与媒体侧审核 |
| 单号展示与复制（线下对账） | 媒体账户充值、扣费与结算 |
| 手工录入 / Excel 导入 / 同步触发 | 真实曝光采集与反作弊 |
| 看板聚合、筛选、导出入口 | 跨渠道归因与投放算法 |
| 日志与审批意见展示 | 用户账号创建、组织架构维护 |
| 截图与演示所需的稳定布局 | 媒体后台代理登录与代操作 |
| 厂商主数据维护、计划—厂商多选 | 媒体侧真实下单、充值、结算 |

## 3 身份与权限

只有两类身份，**不做角色叠加**：

| 身份 | 典型操作 | 数据范围 |
|---|---|---|
| 管理员 `admin` | 审核、发布、厂商维护、模拟参数、用户管理、日志查询 | 全部数据与配置 |
| 普通用户 `user` | 新建计划、提交审核、录入数据、导出报表 | 本人创建的计划 |

- 权限码格式「资源:动作」，与后端一致：`campaign:read / create / update / delete / submit / approve / publish / pause / finish / close`、`stats:write / import / sync / adjust`、`report:export`、`dashboard:read`、`vendor:read / manage`、`mock:manage`、`system:log`、`project:read`。
- 后端 `admin: ['*']`，`user` 为固定集合；前端按钮级权限用 `v-perm` 指令，**前端权限只影响可见性**，写操作后端二次校验。
- 普通用户访问他人计划，后端返回 **1004** 而非 1003（防止探测数据存在性）。

## 4 信息架构与路由

建设范围：**九个页面模块** = 登录、工作台、投放计划、发布投流向导、投放详情、数据回收、数据看板、报表中心、管理。

| 路由 | 页面 | 权限 | 说明 |
|---|---|---|---|
| `/login` | 登录 | 匿名 | 左右分栏；账号密码；失败三次需等待一分钟 |
| `/dashboard` | 工作台 | 登录 | 指标卡 + 趋势 + 渠道占比 + 待办 |
| `/campaign` | 投放计划 | 登录 | 列表、筛选、批量操作 |
| `/campaign/create` | 发布投流 | 登录 | 四步向导，支持草稿 |
| `/campaign/:id` | 投放详情 | 登录 | 概览 / 分日数据 / 人群分布 / 素材 / 操作日志 |
| `/stats` | 数据回收 | 登录 | 手工录入、Excel 导入、同步记录 |
| `/report` | 报表中心 | 登录 | 日报、周报、结案报告导出 |
| `/admin` | 管理 | 管理员 | 单页五页签：用户、厂商、模拟参数、字典、操作日志 |
| ⚠️ 缺失 | **数据看板** | 登录 | 方案给了 4.6 节与六张图，但路由表无对应路由（见差距清单 G3） |

素材管理：**只保留入口与列表展示**，不含上传后转码与审核流程；方案中无独立路由。

## 5 核心业务对象与状态机

- **投放计划 Campaign**：一次可独立排期、独立核算的投放单元，平台核心对象。
- **投放单号**：发布后生成，形如 `DC20261123-0007`（DC + 发布日 + 计划标识），用于对账与导入模板。
- **指标**：曝光量 Impressions、曝光人数 Reach（去重触达，不可由曝光量推算）、点击率 CTR（**点击人数 ÷ 曝光人数**，与常规 clicks/impressions 不同，必须统一）、消耗、完成率。

### 5.1 七态状态机（前后端一致）
| 当前 | 事件 | 目标 | 附加动作 |
|---|---|---|---|
| draft 草稿 | submit 提交审核 | pending 待审核 | 校验必填项与预算，写提交记录 |
| pending 待审核 | approve 审核通过 | scheduled 已排期 | 记录审核意见与审核人 |
| pending | reject 驳回 | draft | 记录驳回原因，解锁编辑 |
| pending | withdraw 撤回 | draft | 仅创建人可撤回 |
| scheduled 已排期 | publish 发布 | running 投放中 / 保持 scheduled | 生成单号，写定向与预算快照 |
| running | pause 暂停 | paused | 记录暂停时间与原因 |
| paused | resume 恢复 | running | 记录恢复时间 |
| running / paused | finish 结束 | finished | 汇总数据，禁止继续录入 |
| finished 已结束 | close 结案 | closed 已结案 | 生成结案报告编号，转只读 |

前端铁律：**按钮显隐只解决体验**；捕获 **409（2001 状态不允许 / 2002 名称重复 / 2003 预算超限）** 后刷新详情；发布接口后端幂等，前端请求期间禁用按钮并展示加载态。

### 5.2 行操作可见性（按状态 × 身份）
| 状态 | 用户可做 | 管理员额外 |
|---|---|---|
| 草稿 | 编辑、提交审核 | 删除 |
| 待审核 | 查看、撤回（仅创建人） | 审核通过 / 驳回 |
| 已排期 | 查看 | 发布、复制为新计划 |
| 投放中 | 查看、录入数据 | 暂停 |
| 已暂停 | 查看 | 恢复、结束投放 |
| 已结束 | 查看 | 生成结案报告 |
| 已结案 | 查看、导出报告 | 归档 |
| 批量 | 仅「批量导出」「批量归档」，**不提供批量发布** | 同左 |

> 注：原文 4.2.3 与 5.1 表 5-1 对「删除」与「审核」按钮的归属表述不完全一致，已在差距清单 G9 记录，**按上表作为待确认基线**。

## 6 各模块要点

### 6.1 登录与工作台
- 登录：左栏项目名 + 一句业务说明，右栏账号密码；令牌存 **sessionStorage**（关浏览器即失效）。
- 工作台三段式：**六张指标卡**（可点击下钻并自动带入筛选）→ 曝光趋势折线 + 渠道占比环形 → 待审核计划 + 最近更新数据。

| 指标 | 口径 | 示例 | 下钻 |
|---|---|---|---|
| 计划曝光量 | 周期内计划目标之和 | 16,880,000 | 计划列表 |
| 实际曝光量 | 分日曝光求和 | 17,125,369 | 分日明细 |
| 曝光完成率 | 实际 ÷ 计划 | 101.45% | 完成率排序 |
| 曝光人数 | 媒体侧去重触达 | 196,942 | 人群分布 |
| 点击率 | 点击人数 ÷ 曝光人数 | 1.15% | 点击明细 |
| 在投计划 | status=running 计数 | 3 | 在投列表 |

### 6.2 投放计划列表
- 筛选：计划名称（模糊/回车）、投放单号（精确/支持扫码枪）、渠道（多选/全选）、状态（单选 7 态）、投放周期（日期范围，**有交集即命中**）、项目（单选，默认当前项目）。
- **筛选条件写入地址栏查询参数**，刷新 / 分享链接可还原。
- 列：单号 150 / 名称 自适应（两行省略 + 悬浮全称）/ 渠道 100（图标+文字）/ 厂商 140（标签，超 2 个显示 +N）/ 状态 90（彩色标签）/ 排期 180（投放中显示「第 N 天」）/ 计划曝光 120 / 实际曝光 120 / 完成率 100（>100% 强调色）/ 操作 160。
- 千分位、右对齐；未发布单号显示「—」，发布后一键复制。

### 6.3 发布投流向导（四步）
| 步骤 | 内容 | 关键校验 |
|---|---|---|
| 一 基础信息 | 名称、项目、渠道、厂商、目标、合同 | 名称 2–40 字且同项目唯一；渠道已开通；厂商 ≥1 且 ≤5、启用态；目标三选一（曝光/点击/线索） |
| 二 人群定向 | 地域（省/市级联多选）、性别、年龄段、兴趣标签 | 地域 ≥1；年龄段不重叠；兴趣 ≤5 |
| 三 排期与预算 | 起止日期、日预算、总预算、目标曝光、出价方式 | 开始 ≥ 当日且 ≤ 未来 30 天；结束 ≥ 开始且跨度 ≤365 天；日预算 >0 两位小数；总预算 ≥ 日预算且 ≤项目剩余预算；目标曝光 >0 并给参考值估提示 |
| 四 确认发布 | 信息复核（只读）、素材 ≤10、发布方式、备注 ≤200、确认勾选 | 勾选后方可提交；「直接发布」仅管理员 |

- 横向步骤条：已完成步骤可点击回退（回退不重新校验），未完成不可跳过，随时「保存草稿」退出。
- 校验失败：滚动定位并聚焦字段 + 步骤条红点；后端业务错误（预算超限 / 渠道未开通）也要定位到具体字段，而非只弹全局提示。
- 提交成功：关闭向导、回列表高亮新记录、顶部提示「已提交审核，预计一个工作日内完成」。

### 6.4 投放详情
顶部概要（名称、单号、状态、渠道、排期、预算）+ 五个页签：
| 页签 | 内容 | 要点 |
|---|---|---|
| 概览 | 指标卡、完成进度、投放日历 | 进度条按曝光完成率，>100% 显示「已达成」 |
| 分日数据 | 日期/曝光量/曝光人数/点击人数/消耗 | 日期范围筛选，**缺失日期补零**；管理员可逐日编辑 |
| 人群分布 | 地域 / 性别 / 年龄三组图 | 与看板共用组件，口径一致 |
| 素材 | 名称、类型、状态 | 只读，跳素材库维护（当前无素材模块） |
| 操作日志 | 时间、操作人、动作、变更内容 | 倒序，可展开前后值 |

### 6.5 数据回收（三种来源 + 模拟生成）
- **手工录入**：数据日期（排期内、不可未来）、曝光量（非负）、曝光人数（≤曝光量）、点击人数（≤曝光人数）、消耗（非负，>日预算 110% 二次确认）、地域/性别/年龄分布（**合计必须等于总曝光**，弹窗实时校验差额并禁止提交）。
- **Excel 导入**（同一弹窗四段式，不跳页）：① 下载模板（六必填列：计划编号、日期、曝光量、曝光人数、点击人数、消耗 + 填写说明页）② 上传（仅 xlsx/csv，≤10MB）③ 前端预校验（必填、数字格式、日期范围、计划归属；错误行标红给原因；**最多展示前 50 条**）④ 下载错误行 ⑤ 确认（共 N 行 / 可导入 M 行 / 异常 K 行）⑥ 结果反馈 + 刷新列表。前端只做格式与范围校验，重复与越权由后端判。
- **数据同步**：仅「投放中 / 已结束」展示；确认框说明范围与预计耗时；执行期按钮加载态、禁关闭；完成提示「已同步 N 天数据，其中 M 天为新增」；数据回收页有同步记录列表（触发方式、开始时间、耗时、结果、失败原因）。
- **模拟生成与调节**：入口两处（管理页按项目批量 / 详情页单条）。参数：目标总曝光（默认=计划目标）、投放曲线（均匀/前低后高/前高后低/周末加权）、点击率（默认 1.00%）、千人曝光成本（默认 12 元）、曝光频次（默认 65）、人群比例、随机种子（默认=计划标识）。
  - 算法：逐日曝光 = 目标总曝光 × 当日权重，叠加 ≤15% 波动；按频次折曝光人数、按点击率折点击人数、按千人成本折消耗；人群维度按权重拆分后用**最大余数法**保证合计严格相等；**覆盖写入**，重复执行不累加；固定种子可复现（后端用 `mulberry32`）。
  - 生成后可在分日数据逐日修改：单元格内编辑，实时重算完成率与点击率，记录调节人/时间/原因（原因必填 ≥10 字），进操作日志；页面**固定标注该计划为模拟数据**。

### 6.6 数据看板
- 指标卡与工作台共用 `KpiCard`，**支持环比**（上一周期同长度区间；无历史数据显示「—」而非 0%）。
- 六张图：曝光趋势（折线，实际 vs 计划双线，可切点击人数）、渠道占比（环形，中心显示总量）、地域分布（横向柱，默认 Top10 + 其他）、性别分布（环形，男/女/未知 + 占比标签）、年龄分布（柱，固定 5 区间按曝光降序）、计划完成率（条形，>100% 强调色）。
- 统一配色顺序与数值格式；**切换筛选不重算颜色映射**，保证同一计划跨图颜色一致。

### 6.7 报表中心
| 报表 | 内容 | 格式 |
|---|---|---|
| 投放日报 | 当日各计划曝光/点击/消耗/完成率 | xlsx |
| 投放周报 | 周维度汇总与环比 | xlsx |
| 结案报告 | 计划信息 + 总体指标 + 分日 + 人群分布 + 结论页 | xlsx、pdf |
| 数据明细 | 按计划与日期展开的原始记录 | xlsx |

导出为**异步任务**：创建任务 → 轮询 → 完成提示 + 下载链接，避免大数据量阻塞。

### 6.8 管理（单页五页签，仅管理员）
页签按需加载，切页不整页刷新；普通用户不显示入口，直访路由跳无权限页。

| 页签 | 内容 | 规则要点 |
|---|---|---|
| 用户 | 新增、启停、重置密码、身份设置 | 只有两类身份；不物理删除；**不能停用自己** |
| 厂商 | 新增、编辑、停用、删除 | 编码全局唯一；名称不唯一；电话脱敏（仅管理员可见全号）；软删除；被计划引用则禁用删除并提示原因；列表显示关联计划数 |
| 模拟参数 | 计划选择（项目/计划/排期，可批量）、参数配置（7 项，可存常用方案）、效果预览（不写库）、生成/覆盖/清空（二次确认 + 日志）、调节记录（可按历史参数重生成） | 顶部固定提示「当前为模拟数据，仅用于流程验证与演示」 |
| 字典 | 渠道字典（名称/图标/是否开通/默认出价方式）、指标口径（名称/公式/小数位/是否看板展示） | 口径字典化，变更不改代码 |
| 操作日志 | 按时间/操作人/对象类型检索、导出 | 普通用户不可见 |

厂商字段：编码（必填唯一）、名称（必填）、所属平台（必填，抖音/微信/小红书/快手/百度等）、联系人、联系电话、状态开关、备注。关联计划数 >0 时删除按钮禁用。

### 7.4 图表

## 9 安全与部署
- 令牌存 sessionStorage，刷新保持、关标签失效；过期前 5 分钟静默续期，过期跳登录并回跳原地址。
- 路由守卫管页面，`v-perm` 管按钮；禁 `v-html`；外链 `rel="noopener noreferrer"`；导出文件后端生成；参数统一编码。
- 手机号脱敏前三后四；导出可配水印（导出人+时间）；日志不记录令牌与密码。
- 构建产物输出 `dist`，Nginx `try_files` 回退 + `/api/` 反代；静态资源 30d immutable；**版本目录 + 软链**发布，回滚切软链，保留最近 5 版；`.env.production` 注入接口地址、项目名、版本号。

## 13 与后端方案的关键对齐结论
| 项 | 结论 |
|---|---|
| 响应信封 | `{ code, message, data, traceId }`，`code=0` 成功 |
| 列表结构 | `items / total / page / pageSize` |
| 数值传输 | **金额与曝光量以字符串传输**，前端格式化展示，禁止浮点 |
| 错误码 | 1001 参数、1002 401、1003 403、1004 404、2001 状态不允许、2002 名称重复、2003 预算超限、2004 厂商被引用、2005 厂商停用、3001/3002/3003 导入与模拟、4001 媒体、5000 系统 |
| 写接口幂等 | 支持 `Idempotency-Key` 请求头，重复提交返回首次结果 |
| 令牌 | 有效期 2 小时（前端「5 分钟静默续期」需后端提供续期能力，见 G4） |
