# 投流统计平台

> 2026 年太仓分公司全域融数智能投放服务 · 投流统计平台
> 范围：**只做前端**；管理端已合并，平台统一使用管理员入口，后端接口由既有服务提供
> 当前阶段：**业务页面与系统管理已接真实内网后端**（192.168.9.224:3000）

## 一、项目说明

把「投放动作」与「投放结果」结构化为可查询、可核验、可导出的数据资产。页面只负责展示与操作，数据由后端统一生成与维护；前端不提供模拟数据入口，也不包含 Mock 数据层。

- 技术栈：Vue 3.5 + TypeScript 5.4 + Vite 5.2 + Vue Router 4.6 + Pinia 2.1 + Element Plus 2.14 + ECharts 5.5 + Day.js 1.11 + SheetJS（按需加载）
- 设计系统：单色社论风（发际线、无阴影、小圆角、语义色仅用于点/线/进度），支持明暗主题；详见 [DESIGN.md](docs/DESIGN.md)
- 登录：唯一入口 `/admin/login`，只允许管理员账号；不再有普通用户登录页
- 已实现页面：工作台、投放计划、发布投流向导、投放详情、数据回收、数据看板、报表中心、系统管理（管理员账号 / 项目管理 / 厂商 / 字典 / 操作日志五页签）（+ 404）
- 数据来源：内网后端 `http://192.168.9.224:3000/api/v1`，开发环境通过 Vite 代理同源访问

### 关键业务规则

- 全站管理员权限，不再有审核角色；计划直接发布，没有「待审核」状态；
- 创建计划时：
  - 开始日期未到 → 进入「已排期」，不生成投放单号；
  - 到开始日期 → 后端自动发布，生成投放单号并转为「投放中」；
  - 开始日期已到/今天 → 直接发布并开始投放；
- 系统管理可维护项目；管理端查询默认覆盖全部项目，不锁定单个项目；
- 渠道使用官方品牌图标：抖音、微信、小红书、快手、百度；
- 报表中心只提供 xlsx，PDF 选项已移除。
- 目标曝光量限制在 1,000–100,000,000 次，且不能超过总预算按千人曝光成本 12 元估算的范围。

## 二、环境与启动

### 环境要求

- Node.js 18+、pnpm 8+
- 后端 `http://192.168.9.224:3000` 可访问（代理已在 `vite.config.ts` 配置好）

### 命令

```bash
pnpm install      # 安装依赖
pnpm dev          # 开发服务，默认 http://localhost:5273
pnpm build        # 生产构建到 dist/
pnpm preview      # 本地预览 dist/
pnpm type-check   # vue-tsc 严格类型检查
```

启动日志会打印两个地址（监听 `0.0.0.0`）：

```text
Local:   http://localhost:5273/
Network: http://192.168.9.223:5273/   （局域网内可访问）
```

### 账号

平台只保留管理员账号体系，账号由后端统一发放，前端不提供新增账号入口。

| 账号 | 密码 | 身份 |
|---|---|---|
| `root` | `root` | 管理员（唯一登录入口 `/admin/login`） |

### 演示数据

数据库初始为空或调试期被重置时，通过后端接口播种（幂等）：

```bash
python scripts/seed-real.py
```

脚本会创建项目、6 家厂商、9 条计划及分日/人群数据；不再创建普通用户账号。

## 七、接口层与约定

- 所有页面只调用 `src/api/*`，统一走 `request()`（axios，`baseURL=/api/v1`）。
- 开发代理：`vite.config.ts` 的 `server.proxy['/api']` → `http://192.168.9.224:3000`。
- 生产环境：Nginx 反代 `/api/`；`.env.production` 只保留 `VITE_API_BASE`。
- 字段映射集中在 `src/api/real.ts`，后端字段变化只改这一层。
- 同步接口 `POST /campaigns/{id}/sync` 返回 `updatedDays` / `message`，前端兼容旧 `days` 字段。
- 历史 pending 计划前端按「已排期」展示；发布时如后端仍为 pending，会自动补审核再发布。
- 渠道图标与图表统一使用品牌色：抖音 `#161823`、微信 `#07C160`、小红书 `#FF0033`、快手 `#FF4906`、百度 `#2932E1`。

## 十、响应式适配

站点按 PC、平板、移动三档适配，断点为 1279 / 900 / 720 / 560：

| 端 | 宽度 | 布局行为 |
|---|---|---|
| PC | ≥1280px | 侧栏 248px；KPI 3 列；图表/双栏页面按设计稿多列；表格完整展示 |
| 平板 | 768–1279px | 内容边距 16px；图表与双栏页逐级合并为单列；表格横向滚动，避免列被压缩；901–1279 侧栏完整，≤900 收为 64px 图标栏 |
| 移动 | ≤767px | 侧栏 64px 图标栏；标题操作区纵向换行；KPI 2 列（≤560 单列）；发布向导步骤 2×2、表单单列、渠道 2 列；表格横向滚动 |

具体处理：

- 表格统一放进滚动容器并取消固定操作列，≤1279px 设置最小宽度（计划表 1100px，通用 980px，管理端 1120px），窄屏左右滑动查看，不压缩列；
- 发布向导移动端：步骤条 2×2、名称/项目/合同/预算等表单单列、目标卡单列；
- 登录页 ≤900px 隐藏左侧品牌区，表单占满；
- 移动端筛选栏单列、查询/重置按钮整行；列表头纵向排列；状态分类自动换行；分页只保留前后页和页码；
- 表格上方显示「左右滑动查看完整表格」提示；
- 移动端页面不产生整页横向溢出，横向滚动只发生在表格内部；
- 图表按容器宽度自适应，隐藏容器不提前初始化 ECharts。
